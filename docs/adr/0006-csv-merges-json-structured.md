# CSV serializes phone numbers as a merged human-readable string; API JSON serializes them as a structured array

The same **FacilityPhoneNumber** data is rendered in two deliberately different shapes. The CSV exporter joins all rows into a single `phone_numbers` cell using `"; "` as separator, with the primary entry suffixed `" (primary)"`, formatting each entry as `"+CC NNN-NNN-NNNN xEXT (primary)"` inline (e.g. `"+1 604-437-1940 x12 (primary); +1 604-987-6543"`). The API JSON serializer instead returns `phone_numbers` as an array of structured objects (`{ country_code:, number:, extension:, description:, primary: }`) with raw stored digits and no formatting, so the frontend can render freely. We deliberately do not add a `formatted` field to the JSON payload. Alternatives considered: shared formatted string in both (loses JSON structure); raw structured data in both (unusable CSV for humans); shared `PhoneFormatter` service (rejected — only CSV needs formatting, so inline is cheaper than a service object).

The admin show view does **not** use the CSV-style merged string: each **FacilityPhoneNumber** is rendered with its attributes shown separately, description on its own second line.
