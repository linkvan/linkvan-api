# Vancouver City syncer dual-writes phone data and drops FacilityPhoneNumber on validation failure

The Vancouver City syncer writes the raw upstream phone string to `Facility#phone` (legacy, unmodified) AND additionally attempts to build a `FacilityPhoneNumber` (digits-stripped, marked `primary: true` when no primary exists yet). If the constructed `FacilityPhoneNumber` fails validation, the syncer silently skips it but still saves `Facility#phone`. This is intentional: the messy, inconsistent historical phone data is kept visible in the legacy column so parsing blindspots surface for manual review, rather than failing the entire sync or silently losing the phone number. Alternatives considered: syncer populates only `FacilityPhoneNumber` (loses raw data on parse failures); syncer fails the entire facility on phone-number validation failure (fatal).
